# はじめての ja-normalize — GitHub の画面だけで使う手順

GitHub Actions を使ったことがない方向けの手順書です。
コマンド操作は不要で、ブラウザーだけで完結します。

---

## この仕組みでできること

`i18n/ja` の日本語ドキュメントに含まれるカタカナ用語の表記ゆれ
(例: `ユーザ` → `ユーザー`) を、用語集にもとづいて自動でそろえます。

使い方は 2 通りです。

| やりたいこと | 方法 |
| --- | --- |
| 今あるドキュメント全体をまとめて直したい | **手動実行** (下記 手順 2) |
| 編集した内容に表記ゆれがないか確認したい | **自動チェック** (下記 手順 3。操作不要) |

---

## 準備: 1 度だけ必要なこと

自動実行の設定ファイルは、リポジトリの **既定のブランチ (`main`)** に入っている必要があります。
このブランチをまだ `main` にマージしていない場合は、先に Pull Request をマージしてください。
マージが済むまで、手順 2 の「Run workflow」ボタンは表示されません。

---

## 手順 1: Actions タブを開く

1. ブラウザーで GitHub のリポジトリを開きます。
2. 上部のタブから **Actions** をクリックします。
3. 画面左側の一覧から **ja-normalize** をクリックします。

> **「Workflows aren't being run on this forked repository」と表示されたら**
> 画面の緑のボタン **I understand my workflows, go ahead and enable them** を
> 1 度だけクリックすると、以降は使えるようになります。

---

## 手順 2: まとめて修正する (手動実行)

1. 手順 1 の画面右側にある **Run workflow** ボタンをクリックします。
2. 小さな入力欄が開きます。次のように設定します。

   | 項目 | 選ぶもの |
   | --- | --- |
   | Use workflow from | 実行したいブランチ (通常は `main`) |
   | 実行モード | **fix** (修正する) / **check** (確認するだけ) |
   | 対象パス | そのまま (`i18n/ja`) |

   - **まず確認だけしたい場合は `check`** を選んでください。ファイルは変更されません。
   - **実際に直したい場合は `fix`** を選びます。

3. 緑の **Run workflow** ボタンを押します。
4. 1 分ほどで一覧に新しい行が追加され、実行状況が表示されます。

   | 表示 | 意味 |
   | --- | --- |
   | 🟡 黄色の丸 | 実行中 |
   | ✅ 緑のチェック | 正常終了 |
   | ❌ 赤いバツ | 表記ゆれが見つかった (`check` の場合) またはエラー |

5. `fix` を選んだ場合、修正内容をまとめた **Pull Request が自動で作られます**。
   上部の **Pull requests** タブを開いて確認してください。

---

## 手順 3: 修正内容を確認してマージする

1. **Pull requests** タブで、`docs(ja): 日本語テクニカル用語の表記ゆれを正規化`
   というタイトルの Pull Request を開きます。
2. **Files changed** タブで変更内容を確認します。
   - 赤い行が変更前、緑の行が変更後です。
3. 問題がなければ **Merge pull request** → **Confirm merge** を押します。
4. おかしな変換が含まれていた場合は、**マージせずに** 下記「変換してほしくない語がある場合」へ進んでください。

---

## 手順 4: 日々の編集時の自動チェック (操作不要)

`i18n/ja` のファイルを変更して Pull Request を作ると、チェックが自動で走ります。

- ✅ 緑のチェック … 表記ゆれなし。そのまま進めて問題ありません。
- ❌ 赤いバツ … 表記ゆれあり。

赤いバツが出たときは、次の手順で内容を確認できます。

1. Pull Request の下部にある **Details** をクリックします。
2. **Summary** に、どのファイルの何行目にどの表記ゆれがあるかが一覧表示されます。

   ```
   i18n/ja/.../processes.md:42:15: ユーザ → ユーザー
   ```

3. 直し方は 2 通りです。
   - GitHub の画面でそのファイルを開き、鉛筆アイコンから該当箇所を手で修正する
   - 手順 2 の **手動実行 (`fix`)** を実行して、自動修正の Pull Request を作る

---

## 変換してほしくない語がある場合

固有名詞や製品名など、意図的に短い表記のままにしたい語があるときは、
用語集ではなく **例外ファイル** に追記します。

1. GitHub で `tools/ja-normalize/exceptions.tsv` を開きます。
2. 右上の鉛筆アイコン (Edit this file) をクリックします。
3. 末尾に 1 行追加します。**項目の区切りは必ずタブ文字** です。

   ```
   literal	ユーザ定義クラス
   ```

4. 画面下部の **Commit changes** を押します。

---

## 用語を追加・変更したい場合

1. GitHub で `tools/ja-normalize/glossary.tsv` を開きます。
2. 鉛筆アイコンをクリックし、`変換前`・`変換後`・`備考` をタブ区切りで 1 行追加します。

   ```
   ウィンドウ	ウインドウ	例
   ```

3. **Commit changes** を押します。
4. 追加した用語を既存のドキュメントにも適用するには、手順 2 の手動実行 (`fix`) をおこないます。

> 記述する順番は気にしなくて構いません。長い表記が自動的に優先されます。
> 矛盾した定義を書いた場合は、実行時にエラーとして知らせます。

---

## 困ったときは

| 症状 | 対処 |
| --- | --- |
| **Run workflow** ボタンがない | 設定ファイルが既定のブランチ (`main`) にマージされているか確認してください |
| 赤いバツが出た | **Details** → **Summary** に該当箇所の一覧が表示されます |
| 直したくない語が変換された | `exceptions.tsv` に `literal` 行を追加し、再度 `fix` を実行してください |
| 変換結果に納得がいかない | 自動生成された Pull Request はマージしなければ反映されません。閉じて構いません |

---

## 補足: パソコンのコマンドで実行する場合

Node.js が入っている環境では、次のコマンドでも同じことができます。

```bash
npm run ja:check   # 確認だけ
npm run ja:fix     # 修正する
```

詳細は [README.md](README.md) を参照してください。
